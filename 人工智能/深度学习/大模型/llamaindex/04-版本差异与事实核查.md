# 第 4 章 版本差异与事实核查

> 本章解决一个问题：**你在网上抄到的 llama_index 代码为什么一跑就 ImportError。**
> LlamaIndex 从 2023 年到 2025 年经历了三次结构性重写，互联网上 80% 的教程代码停留在 0.6/0.7 时代。
> 本章给出「旧写法 → 新写法」的完整翻译表、断言可信度分级，以及自己核实版本事实的方法。

## 4.0 怎么用这一章

1. 先看 **4.1 分水岭**，确认你手上的代码属于哪一代。
2. 用 **4.2 / 4.3 / 4.4** 的对照表，把旧 import 一行行替换。
3. 遇到报错，查 **4.8 高频过时写法**，按「报错文本 → 原因 → 修法」处理。
4. 对任何断言拿不准，照 **4.9** 的方法自己在本地核实，不要相信任何文档（包括本章）而不验证。

**本章默认基线**：llama-index-core 0.14.x（2025 年主线）。
**重要**：本章所有断言都带可信度标注。标注为「待核实」的，必须在你锁定的版本上用 4.9 的方法验证后再用。

## 4.1 版本分水岭：四次结构性变化

| 版本 | 时间 | 结构性变化 | 影响 |
|---|---|---|---|
| 0.5 / 0.6 | 2023 上 | 单包 `llama-index`，全部代码在一个包里 | 所有老教程的出处 |
| 0.7 | 2023 中 | 引入 `ServiceContext`、`LLMPredictor`；`Index` 家族以 GPT 前缀命名 | 网上最常见的「过时写法」来源 |
| **0.8** | 2023 下 | 去掉 GPT 前缀；`LLMPredictor`/`LangchainEmbedding` 被 LLM/Embedding 抽象取代 | 出现第一批「类不存在」报错 |
| 0.9 | 2023 末 | Agent 体系（`OpenAIAgent`）、`CallbackManager` 稳定 | — |
| **0.10** | 2024-02 | **大拆包**：`llama-index-core` + 各集成包；`ServiceContext` 从顶层移除；引入 `Settings` 全局配置 | **分水岭**，所有旧代码在这一版集中失效 |
| 0.11 | 2024-09 | 事件驱动 `Workflow` 成型；Agent 重构到 workflow 之上（`FunctionAgent`） | 旧 Agent API 开始被替换 |
| **0.12** | 2024-11 | 清理 legacy re-export；`QueryPipeline` 进入弃用通道；Workflow 成为推荐的复杂编排方案 | 第二次集中失效 |
| 0.13 / **0.14** | 2025 | Workflow 实现拆到 `llama-index-workflows` 独立包；Python 最低版本抬升 | 当前主线 |

> 判断你手上代码的年代，最快的办法：**看 import**。
> `from llama_index import GPTSimpleVectorIndex` → 0.7 以前；
> `from llama_index import ServiceContext` → 0.7~0.9；
> `from llama_index.core import Settings` → 0.10 以后（可用）。

## 4.2 命名迁移对照表（旧 → 新）

| 旧（0.7 及以前） | 新（0.8+） | 备注 |
|---|---|---|
| `GPTSimpleVectorIndex` | `VectorStoreIndex` | 最常用，改名后行为一致 |
| `GPTVectorStoreIndex` | `VectorStoreIndex` | 同上 |
| `GPTListIndex` | `SummaryIndex` | 列表索引 |
| `GPTTreeIndex` | `TreeIndex` | 树索引 |
| `GPTKeywordTableIndex` | `KeywordTableIndex` | 关键词表索引 |
| `GPTDocumentSummaryIndex` | `DocumentSummaryIndex` | 文档摘要索引 |
| `GPTEmptyIndex` | 无直接对应 | 用空 `VectorStoreIndex` + 手动插入节点 |
| `LLMPredictor` / `LangchainLLMPredictor` | `llama_index.llms.*` 下的 LLM 类 | 0.8 起废除 predictor 层 |
| `LangchainEmbedding` | `llama_index.embeddings.*` 下的 Embedding 类 | 同上 |
| `SimpleNodeParser`（顶层） | `llama_index.core.node_parser.SentenceSplitter` | `SentenceSplitter` 是主推切分器 |
| `ServiceContext.from_defaults(...)` | `Settings.llm / Settings.embed_model / Settings.node_parser` | 见 4.4 |
| `ComposableGraph` | 无替代（官方不再维护） | **待核实**：0.10 后是否已彻底删除，请按 4.9 核实 |

> ⚠️ 迁移不是纯改名：`GPTSimpleVectorIndex.from_documents(...)` 的**参数语义**也变了，尤其是 `service_context=` 参数在 0.10 之后不再被接受，要改用 `Settings` 或调用处显式传 `llm=` / `embed_model=`。

## 4.3 包与导入路径的变化

### 4.3.1 0.10 拆包后的结构

```text
llama-index-core               抽象层：索引/检索/查询/工作流/Agent/评测
llama-index-llms-<provider>    模型适配：openai / anthropic / ollama / deepseek(走 openai 兼容)
llama-index-embeddings-<provider>  Embedding 适配
llama-index-vector-stores-<db> 向量库适配：chroma / qdrant / milvus / pgvector
llama-index-readers-<x>        数据读取适配
llama-index                   元包：core + 少量默认集成，不要指望它全装
```

### 4.3.2 导入路径三段式

| 要导入的东西 | 0.10+ 正确路径 |
|---|---|
| 核心索引/文档/分块 | `from llama_index.core import VectorStoreIndex, Document, SimpleDirectoryReader` |
| 节点/切分器 | `from llama_index.core.node_parser import SentenceSplitter` |
| 全局配置 | `from llama_index.core import Settings` |
| 检索器 | `from llama_index.core.retrievers import VectorIndexRetriever` |
| 查询引擎 | `from llama_index.core.query_engine import RetrieverQueryEngine` |
| 后处理 | `from llama_index.core.postprocessor import SimilarityPostprocessor` |
| 工作流 | `from llama_index.core.workflow import Workflow, StartEvent, StopEvent, step`（0.11+；0.14 起也可用 `from workflows import ...`，**待核实**） |
| Agent | `from llama_index.core.agent.workflow import FunctionAgent`（0.11+） |
| OpenAI 模型 | `from llama_index.llms.openai import OpenAI`（来自 `llama-index-llms-openai`） |
| OpenAI Embedding | `from llama_index.embeddings.openai import OpenAIEmbedding`（来自 `llama-index-embeddings-openai`） |
| Chroma 向量库 | `from llama_index.vector_stores.chroma import ChromaVectorStore`（来自 `llama-index-vector-stores-chroma`） |

### 4.3.3 仍然能用的顶层 import

`from llama_index import VectorStoreIndex` 这种写法在拆包后被元包以 re-export 方式保留过一段时间。
**可信度：低（随版本变化，0.12 前后收窄）。** 生产代码一律写成 `from llama_index.core import ...`，不要依赖顶层兼容。

## 4.4 ServiceContext → Settings 迁移（最常见的迁移工作）

### 4.0 时代的旧写法（现在会报 ImportError）

```python
# ❌ 0.10+ 下 from llama_index import ServiceContext 直接 ImportError
from llama_index import ServiceContext, VectorStoreIndex, SimpleDirectoryReader

service_context = ServiceContext.from_defaults(
    llm=my_llm,
    embed_model=my_embed_model,
    chunk_size=512,
)
index = VectorStoreIndex.from_documents(docs, service_context=service_context)
query_engine = index.as_query_engine(service_context=service_context)
```

### 新写法：Settings 是全局单例，调用处可局部覆盖

```python
from llama_index.core import Settings, VectorStoreIndex, SimpleDirectoryReader
from llama_index.core.node_parser import SentenceSplitter
from llama_index.llms.openai import OpenAI
from llama_index.embeddings.openai import OpenAIEmbedding

# 只在应用启动处设置一次
Settings.llm = OpenAI(model="gpt-4o-mini", temperature=0)
Settings.embed_model = OpenAIEmbedding(model="text-embedding-3-small")
Settings.node_parser = SentenceSplitter(chunk_size=512, chunk_overlap=64)

docs = SimpleDirectoryReader("./data").load_data()
index = VectorStoreIndex.from_documents(docs)          # 自动使用 Settings
query_engine = index.as_query_engine()                 # 同上
```

### 迁移对照

| ServiceContext 时代 | Settings 时代 |
|---|---|
| `ServiceContext.from_defaults(llm=...)` | `Settings.llm = ...` |
| `ServiceContext.from_defaults(embed_model=...)` | `Settings.embed_model = ...` |
| `from_defaults(chunk_size=512)` | `Settings.node_parser = SentenceSplitter(chunk_size=512)` |
| `from_defaults(callback_manager=...)` | `Settings.callback_manager = ...` |
| `service_context=sc` 作为参数传入 | 删除该参数；需要隔离时在调用处显式传 `llm=` / `embed_model=` |
| 多个 ServiceContext 并行 | 只有一个 Settings 全局值；多租户/多模型用显式传参或函数内临时保存-恢复 |

### 两个坑

- **全局单例污染**：`Settings.embed_model` 一旦被某处改掉，后面所有索引都跟着变。测试里必须显式重置。
- **写索引和查索引必须用同一个 embedding 模型**。换成不同的模型不会报错，只会让检索结果全部失真——这是静默失败。

## 4.5 Agent 与 Workflow 的世代替换

| 年代 | Agent 写法 | 状态 |
|---|---|---|
| 0.7~0.9 | `from llama_index.agent.openai import OpenAIAgent` | 已移除（**待核实**具体移除版本，0.11+ 下 ImportError） |
| 0.9~0.10 | `ReActAgent` / `OpenAIAgent` + `AgentRunner` | 0.11 起不再推荐 |
| 0.11+ | `from llama_index.core.agent.workflow import FunctionAgent` | 当前推荐 |
| 0.11+ | 自定义 `Workflow`（事件驱动） | 复杂流程首选 |
| 0.14+ | `llama-index-workflows` 独立包，模块名 `workflows` | **待核实** core 内 re-export 的保留程度 |

Agent 简化写法（0.11+）：

```python
from llama_index.core.agent.workflow import FunctionAgent
from llama_index.llms.openai import OpenAI

def multiply(a: float, b: float) -> float:
    """两数相乘。"""
    return a * b

agent = FunctionAgent(tools=[multiply], llm=OpenAI(model="gpt-4o-mini"))
result = await agent.run("12 乘以 7 等于多少")   # run 返回 workflow 句柄，必须 await
print(result)
```

常见误解：`agent.run(...)` 不是同步返回字符串，它是异步 workflow 句柄。
在 FastAPI 里不要套 `asyncio.run`，否则 `RuntimeError: asyncio.run() cannot be called from a running event loop`。

## 4.8 新手最常踩的 12 个过时写法

| # | 报错 / 现象 | 原因 | 修法 |
|---|---|---|---|
| 1 | `ImportError: cannot import name "ServiceContext"` | 0.10 移除 | 改 `Settings`，见 4.4 |
| 2 | `ImportError: cannot import name "GPTSimpleVectorIndex"` | 0.8 改名 | `VectorStoreIndex` |
| 3 | `ImportError: cannot import name "OpenAIAgent"` | Agent 体系重构 | `FunctionAgent` |
| 4 | `ModuleNotFoundError: No module named "llama_index.llms.openai"` | 集成包没装 | `pip install llama-index-llms-openai` |
| 5 | `ModuleNotFoundError: No module named "llama_index.embeddings.openai"` | 同上 | `pip install llama-index-embeddings-openai` |
| 6 | `TypeError: from_documents() got an unexpected keyword argument service_context` | 参数已删 | 删参数，配 `Settings` |
| 7 | `ValueError: No API key found` | 只设了 `OPENAI_API_KEY` 但用的是别的 provider | 设对应环境变量，或显式 `OpenAI(api_key=...)` |
| 8 | 检索全是无关结果、但不报错 | 入库和查询用了不同 embedding 模型 / 维度 | 显式固定同一个模型 |
| 9 | 重启后索引「空了」 | 只 `persist` 了索引，没恢复 docstore/vector_store | 用 `load_index_from_storage` 并挂同一 `StorageContext` |
| 10 | `RuntimeError: asyncio.run() cannot be called from a running event loop` | 在已有事件循环里同步跑 agent | 接口写成 async，或独立 worker |
| 11 | `vector_store.query(query_str=...)` 报参数错误 | 0.10 签名改为 `query(query_str=..., query_embedding=...)`（**待核实**当前签名） | 改用 Index/Retriever 的公开 API，不直接调底层 store |
| 12 | 中文文档切块效果差、召回不到 | 默认切分器按英文标点/空格 | 用 `SentenceSplitter` 并调 `chunk_size/chunk_overlap`，或用中文分隔符的自定义切分 |

## 4.9 自己核实版本事实的四种方法（比任何文档都可靠）

```bash
# 1) 看装了什么版本
pip show llama-index-core llama-index-workflows | findstr /B "Name Version"

# 2) 直接在解释器里问包本身（最可靠）
python -c "import llama_index.core as c; print(c.__version__)"
python -c "from llama_index.core import Settings; print(Settings.llm, Settings.embed_model)"

# 3) 探针：某个符号到底还在不在（不抛异常就说明可用）
python -c "from llama_index.core.workflow import Workflow, step; print('workflow ok')"
python -c "from llama_index.core.query_pipeline import QueryPipeline; print('qp ok')"

# 4) 在源码里确认签名（比文档准）
python -c "import inspect, llama_index.core.retrievers as r; print(inspect.signature(r.VectorIndexRetriever.__init__))"
```

补充两条：

- **官方文档**：`developers.llamaindex.ai/python/framework/`（新版站点，旧的 `docs.llamaindex.ai` 会跳转过来）。中文镜像 `developers.llamaindex.org.cn`。
- **CHANGELOG**：GitHub 仓库 `run-llama/llama_index` 根目录的 `CHANGELOG.md`，按版本号搜你要断言的关键词。

## 4.10 锁定版本策略（避免下次再被迁移打脸）

```text
pyproject.toml / requirements.txt 里的正确姿势：
  llama-index-core>=0.14,<0.15
  llama-index-llms-openai>=0.4,<0.5
  llama-index-embeddings-openai>=0.3,<0.4
  llama-index-vector-stores-chroma>=0.4,<0.5

不要写：
  llama-index            （元包，隐式版本组合不可控）
  llama-index-core        （无上界，小版本漂移直接破坏 API）
```

升级流程（每次升级都走一遍）：

1. 在分支里改版本号，跑通「建索引 → 查询 → 评测集」三步。
2. 用 4.9 的探针命令把用到的符号全跑一遍。
3. 记录 CHANGELOG 里的 breaking change。
4. 评测分数持平或提升才合入。

## 本章速查卡

1. **看 import 判年代**：GPT 前缀、ServiceContext、LLMPredictor 出现在代码里，就是 0.9 以前的代码。
2. **ImportError 找版本，ModuleNotFoundError 找包**：前者改代码，后者改依赖。
3. **ServiceContext 的全部参数都有 Settings 对应位**：llm / embed_model / node_parser / callback_manager。
4. **embedding 模型必须入索引与查询一致**，换模型不报错但会静默失真。
5. **标「待核实」的断言，上线前用 4.9 的探针自测**——文档再好也可能落后于你装的那个小版本。
