# 第 3 章 可直接运行的最小示例与工程实践

本章目标只有一个：**把一条能跑起来的链路交到你手上**。所有代码都在一个空目录里从零开始，按顺序复制即可运行；每段都标明对应文件、依赖和验证方式，跑不通时能立刻判断是「装错了」「写错了」还是「版本漂了」。

写作基线是 LlamaIndex **0.11+ / 0.12+ 主线**（撰写时 PyPI 上 `llama-index-core` 主线已到 0.14.x）。**0.10 前后的旧写法会单独标注并给出替代方案**——你在网上搜到的博客、GitHub issue、内训材料绝大多数仍是 0.9/0.10 时代写法，直接抄会撞上一批 `ImportError`。

> 版本约定：以 0.11 引入、0.12 稳定的写法为基础，同时标注 0.13 / 0.14 的变化。凡标注「**需对照官方文档核实**」处，说明该 API 在 0.12→0.14 间发生过调整，升级前请以你实际安装版本的文档为准。

## 3.0 版本对照：0.10 之前 vs 0.11 之后

这一节是全章地基。LlamaIndex 在 0.10~0.14 之间做过一次拆包、一次删类，不知道这两次调整，后面每个例子都会踩坑。

| 主题 | 0.10 之前（旧） | 0.11 / 0.12（主线） | 0.13 / 0.14（当前） |
| --- | --- | --- | --- |
| 包结构 | 单体 `llama-index`，集成内置 | 拆成 `llama-index-core` + 若干 `llama-index-*` 集成包 | 同左；0.14 起 Workflow 实现进一步拆到 `llama-index-workflows` |
| 全局配置 | `ServiceContext.from_defaults(...)` | `Settings.llm` / `Settings.embed_model` / `Settings.node_parser` | 同左 |
| Query 编排 | `QueryPipeline` | 仍可用但已不推荐 | **0.13 起移除**，改用 Workflow |
| Agent | `OpenAIAgent.from_tools`、`AgentRunner.from_llm(agent_cls=ReActAgent)` | 新增 workflow 版 `FunctionAgent` / `AgentWorkflow`，旧类带弃用警告 | **0.13 起旧 agent 类全部删除**（`FunctionCallingAgent`、`AgentRunner`、`OpenAIAgent` 等） |
| 对话记忆 | `ChatMemoryBuffer.from_defaults(...)` | 仍可用 | 0.12 起推荐 `Memory.from_defaults(...)`，`ChatMemoryBuffer` 标记为 Deprecated |
| 默认 chat engine | `as_chat_engine()` 走 agent | 仍走 agent | **0.13 起默认改为 CondensePlusContextChatEngine**，agent 型 chat engine 移除 |
| Python 版本 | 3.8+ | 3.9+ | **0.14 起要求 3.11+** |

四个高频「抄到旧代码」的报错，本质都在这张表里：

```text
ImportError: cannot import name "ServiceContext" from "llama_index"
ImportError: cannot import name "OpenAIAgent" from "llama_index.agent.openai"
ImportError: cannot import name "QueryPipeline" from "llama_index.core.query_pipeline"
ModuleNotFoundError: No module named "llama_index.llms.openai"
```

前三个是「类被删了」，最后一个是「集成包没装」。**判据：`ImportError: cannot import name` 说明版本 API 变了，去改代码；`ModuleNotFoundError: No module named llama_index.xxx` 说明包没装对，去改依赖。** 这个区分能让你在 30 秒内决定动哪一边。

## 3.1 pip 安装清单：core 与集成包分离

### 3.1.1 拆包规则

0.10 起 LlamaIndex 采用「内核 + 按需集成」结构：

- `llama-index-core`：抽象层，`VectorStoreIndex`、`IngestionPipeline`、`QueryEngine`、`ChatEngine`、`Workflow`、`FunctionAgent`、评测器都在这里，**不含任何具体模型或数据库客户端**。
- `llama-index-llms-*` / `llama-index-embeddings-*`：模型供应商适配，如 `llama-index-llms-openai`、`llama-index-embeddings-huggingface`。
- `llama-index-vector-stores-*`：向量库适配，如 `-chroma`、`-qdrant`、`-pgvector`。
- `llama-index-readers-*` / `llama-index-readers-file`：文件解析器。
- `llama-index`：**元包**，只装 core 加少量默认集成，别指望它把你要的都装上。生产项目直接写 `llama-index-core` + 明确集成包，避免元包隐式引入的版本组合。
- `llama-index-workflows`：0.14 起 Workflow 的真正实现（模块名 `workflows`），`llama_index.core.workflow` 保留为兼容 re-export。是否要直接依赖它，**需对照官方文档核实**。

### 3.1.2 按场景的安装清单

**A. 最小内核（只验证框架能力，不接外部服务）**

```bash

```

core 自带文本类 `SimpleDirectoryReader`、`SentenceSplitter`、内存版 `SimpleVectorStore`、`MockLLM`、`MockEmbedding`，以及索引/查询/对话/工作流/agent/评测器。**这条路径可完全离线跑通全链路**，是本机调试与 CI 的首选。

**B. 生产 RAG（OpenAI 系模型；DeepSeek、通义等 OpenAI 兼容接口同样适用）**

```bash

```

**C. 完全本地、无 API Key（离线或内网部署）**


## 3.2 完整链路：Loader → IngestionPipeline → VectorStoreIndex → QueryEngine

给两份代码：一份**完全离线**（先证明链路通），一份**生产接线**（换真实模型与向量库）。骨架一致，差别只在 `Settings`、`vector_store` 和持久化位置。先跑离线版是强烈建议的顺序——它把所有「模型配额、网络、API Key」变量排除，剩下的错误一定是你代码里的。

### 3.2.1 第一版：离线可跑的最小闭环

文件 `mini_rag.py`，依赖仅 `llama-index-core`。

```python
"""最小闭环：读文件 -> 切块 -> 建索引（内存）-> 问答。无需任何 API Key。"""
from llama_index.core import Settings, SimpleDirectoryReader, VectorStoreIndex
from llama_index.core.embeddings import MockEmbedding
from llama_index.core.ingestion import IngestionPipeline
from llama_index.core.llms import MockLLM
from llama_index.core.node_parser import SentenceSplitter

# 1) 全局配置：0.11+ 用 Settings 取代 ServiceContext
Settings.llm = MockLLM(max_tokens=256)
Settings.embed_model = MockEmbedding(embed_dim=8)
Settings.node_parser = SentenceSplitter(chunk_size=256, chunk_overlap=32)

# 2) Loader：读取目录下所有 txt/md（纯文本 core 即可解析）
docs = SimpleDirectoryReader(
    input_dir="./data",
    required_exts=[".txt", ".md"],
    recursive=True,
    filename_as_id=True,      # 让节点 id 稳定，便于增量更新与去重
).load_data()
print(f"loaded {len(docs)} documents")

# 3) IngestionPipeline：切块 + 嵌入，显式控制而不是靠默认值
pipeline = IngestionPipeline(
    transformations=[
        SentenceSplitter(chunk_size=256, chunk_overlap=32),
        Settings.embed_model,
    ],
)
nodes = pipeline.run(documents=docs)
print(f"produced {len(nodes)} nodes")

# 4) VectorStoreIndex：nodes 已切好并带向量，直接建索引
index = VectorStoreIndex(nodes)

# 5) QueryEngine
query_engine = index.as_query_engine(similarity_top_k=3)
response = query_engine.query("文档主要讲了什么？")
print("ANSWER:", response.response)
print("SOURCES:", len(response.source_nodes))
```

准备数据：

```bash
mkdir -p data && printf "# 测试文档\n\n这是一个用于验证链路的示例文档。\n" > data/hello.md
```

**预期输出**：`loaded 1 documents` → `produced N nodes` → `ANSWER:` 后是 MockLLM 的固定文本 → `SOURCES: 3`（或更少）。

**为什么用 `VectorStoreIndex(nodes)` 而不是 `VectorStoreIndex.from_documents(docs)`？**

- `from_documents` 内部会自己再切分、再嵌入。若你已在 pipeline 里切过、嵌入过，再传 `transformations` 就是**二次切分**：节点粒度变碎、向量数翻倍，且**不会报错**。
- 显式调 pipeline 的好处：可持久化缓存、可去重、能看到中间产物数量。这条链路「可观测」，后者只是「demo 顺手」。

> 若坚持一体化写法：`VectorStoreIndex.from_documents(docs, transformations=[splitter], embed_model=...)`，此时**不要再设 `Settings.node_parser`**，两处配置冲突是常见坑。

### 3.2.2 第二版：生产接线（兼容接口 + Chroma + 持久化）

文件 `ingest.py`（索引构建）与 `qa.py`（查询服务）分开，这是工程上更实用的拆法：构建离线批量跑，查询在线低延迟。

```python
"""ingest.py —— 构建索引并持久化。可重复执行（带去重缓存）。"""
import os
from pathlib import Path

import chromadb
from llama_index.core import (
    Document,
    Settings,
    SimpleDirectoryReader,
    StorageContext,
    VectorStoreIndex,
)
from llama_index.core.extractors import TitleExtractor
from llama_index.core.ingestion import DocstoreStrategy, IngestionPipeline
from llama_index.core.node_parser import SentenceSplitter
from llama_index.core.storage.docstore import SimpleDocumentStore
from llama_index.embeddings.openai import OpenAIEmbedding
from llama_index.llms.openai import OpenAI
from llama_index.vector_stores.chroma import ChromaVectorStore

DATA_DIR = Path("./data")
PERSIST_DIR = Path("./storage")

# ---- 模型：OpenAI 兼容接口（DeepSeek 改 api_base 即可）----
# 注意：api_base / base_url 参数名在不同小版本间有重合与更替，二者其一可用
Settings.llm = OpenAI(
    model="gpt-4o-mini",
    api_key=os.environ["OPENAI_API_KEY"],
    temperature=0.1,
)
Settings.embed_model = OpenAIEmbedding(
    model="text-embedding-3-small",
    api_key=os.environ["OPENAI_API_KEY"],
)

# ---- 向量库：Chroma 本地持久化 ----
chroma_client = chromadb.PersistentClient(path=str(PERSIST_DIR / "chroma"))
collection = chroma_client.get_or_create_collection("docs")
vector_store = ChromaVectorStore(chroma_collection=collection)

storage_context = StorageContext.from_defaults(vector_store=vector_store)

# ---- Loader ----
documents: list[Document] = SimpleDirectoryReader(
    input_dir=str(DATA_DIR),
    required_exts=[".pdf", ".docx", ".md", ".txt"],
    recursive=True,
    filename_as_id=True,
).load_data()

# ---- IngestionPipeline：切块 + 元数据抽取 + 嵌入 + 去重 ----
pipeline = IngestionPipeline(
    transformations=[
        SentenceSplitter(chunk_size=512, chunk_overlap=64),
        TitleExtractor(nodes=5, llm=Settings.llm),  # 可选：给每个块补标题元数据
        Settings.embed_model,
    ],
    docstore=SimpleDocumentStore(),          # 去重与幂等更新的依据
    docstore_strategy=DocstoreStrategy.UPSERTS,  # 已存在则更新，不存在则插入
    vector_store=vector_store,
)

# 断点续跑：先恢复 docstore 与缓存，再跑
if (PERSIST_DIR / "pipeline").exists():
    pipeline.load(persist_dir=str(PERSIST_DIR / "pipeline"))

nodes = pipeline.run(documents=documents)
print(f"ingested {len(nodes)} nodes")

pipeline.persist(persist_dir=str(PERSIST_DIR / "pipeline"))
index = VectorStoreIndex.from_vector_store(
    vector_store=vector_store,
    embed_model=Settings.embed_model,
)
index.storage_context.persist(persist_dir=str(PERSIST_DIR / "index"))
print("index persisted")
```

```python
"""qa.py —— 加载持久化索引并查询。进程启动即可用，不需要重建。"""
from llama_index.core import Settings, StorageContext, load_index_from_storage
from llama_index.embeddings.openai import OpenAIEmbedding
from llama_index.llms.openai import OpenAI

Settings.llm = OpenAI(model="gpt-4o-mini", temperature=0.1)
# 关键：加载索引时必须用与建索引时同一个 embedding 模型，否则检索结果无意义
Settings.embed_model = OpenAIEmbedding(model="text-embedding-3-small")

storage_context = StorageContext.from_defaults(persist_dir="./storage/index")
index = load_index_from_storage(storage_context)

query_engine = index.as_query_engine(
    similarity_top_k=4,
    response_mode="compact",   # 多块拼接后再生成，token 更省
)
response = query_engine.query("这套系统支持哪些文件格式？")

print(response.response)
for i, sn in enumerate(response.source_nodes, 1):
    node = sn.node
    print(f"[{i}] score={sn.score:.4f} file={node.metadata.get('file_name')} id={node.node_id[:8]}")
```

**两处必须记住的工程约束**：

1. `embed_model` 与 `llm` 在建索引与查询两端必须一致（至少 embedding 模型必须完全一致）。换 embedding 模型等于所有向量作废，必须重建索引。
2. `filename_as_id=True` + `DocstoreStrategy.UPSERTS` 是增量更新能工作的前提。不带稳定 id 时，每次全量重建会留下旧向量（Chroma 里表现为结果重复、排序漂移）。

## 3.3 QueryEngine 最小可运行示例

### 3.3.1 基础查询与来源追溯

```python
from llama_index.core import Settings
from llama_index.core.query_engine import RetrieverQueryEngine
from llama_index.core.response_synthesizers import get_response_synthesizer

query_engine = index.as_query_engine(similarity_top_k=3)
resp = query_engine.query("退款政策是什么？")

print(resp.response)
print("tokens used:", resp.metadata.get("total_token_count"))  # 便于成本核算
for sn in resp.source_nodes:
    print(sn.score, sn.node.metadata.get("file_name"), sn.node.text[:80])
```

`resp.source_nodes` 是本框架最值钱的东西之一：它把回答和原文块一一对应起来。**任何面向最终用户的产品都应该把 source_nodes 渲染成引用**，否则无法排查幻觉。

### 3.3.2 流式输出（Web 场景必备）

```python
query_engine = index.as_query_engine(similarity_top_k=3, streaming=True)
response = query_engine.query("总结一下核心结论")

for token in response.response_gen:
    print(token, end="", flush=True)
```

### 3.3.3 自定义提示词与不编造约束

```python
from llama_index.core import PromptTemplate

QA_TMPL = (
    "以下是检索到的上下文：\n"
    "---------------------\n"
    "{context_str}\n"
    "---------------------\n"
    "只依据上面的上下文回答，不要使用先验知识。\n"
    "如果上下文中没有答案，直接回答「资料中未提及」。\n"
    "问题：{query_str}\n"
    "回答："
)
qa_template = PromptTemplate(QA_TMPL)

query_engine = index.as_query_engine(
    similarity_top_k=4,
    text_qa_template=qa_template,
)
```

三个提示词模板参数分开记，别混：`text_qa_template`（单块/精简回答）、`refine_template`（逐块精炼）、`summary_template`（tree_summarize 用）。用 `response_mode="compact"` 时主要生效的是 `text_qa_template` 加上内置的压缩逻辑。

### 3.3.4 带编号引用的问答

```python
from llama_index.core.query_engine import CitationQueryEngine

citation_engine = CitationQueryEngine.from_args(
    index,
    similarity_top_k=3,
    citation_chunk_size=512,
)
resp = citation_engine.query("不同文档对同一问题的说法有何差异？")
print(resp.response)   # 回答中会出现 [1] [2] 形式的引用编号
```

### 3.3.5 检索质量低时先改这三处，而不是换模型

按性价比排序：

1. 切块参数（`chunk_size` / `chunk_overlap`）：中文文档 512/64 是可用起点；表格与条款类文档降到 256 并加重叠。
2. `similarity_top_k` 与重排：先取 k=10 再重排取前 3，比直接 k=3 稳得多。
3. 加元数据过滤（按 `file_name` / `doc_type` / 时间）缩小检索空间。

```python
from llama_index.core.postprocessor import SimilarityPostprocessor
from llama_index.core.query_engine import RetrieverQueryEngine

retriever = index.as_retriever(similarity_top_k=10)
query_engine = RetrieverQueryEngine.from_args(
    retriever,
    node_postprocessors=[SimilarityPostprocessor(similarity_cutoff=0.75)],
)
```

> 注意：`similarity_cutoff` 的绝对值取决于 embedding 是否归一化。OpenAI embedding 归一化后，0.75 往往偏严，会把正确块也过滤掉；正确做法是先打印 `source_nodes` 的分数分布，再定阈值，别照抄别人的数字。

## 3.4 ChatEngine 最小可运行示例

QueryEngine 是无状态的：每问一句都得自己把上文塞进去。ChatEngine 的作用是**替你管多轮上下文**，包括把「那海外订单呢？」改写成「海外订单的退款政策是什么？」。

### 3.4.1 三步起一个对话引擎

```python
# chat_min.py
from llama_index.core import Settings
from llama_index.core.memory import Memory
from llama_index.llms.openai import OpenAI

Settings.llm = OpenAI(model="gpt-4o-mini", temperature=0.1)

chat_engine = index.as_chat_engine(
    chat_mode="condense_plus_context",   # 0.13+ 的默认值，显式写出来更稳
    similarity_top_k=3,
    memory=Memory.from_defaults(session_id="demo-user", token_limit=3000),
)

print(chat_engine.chat("退款政策是什么？").response)
print(chat_engine.chat("那海外订单呢？").response)   # 依赖上文的指代，能正确改写才算通了
chat_engine.reset()                                   # 清空本轮会话记忆
```

**怎么判断这行代码真的生效**：第二问如果给出泛泛回答，说明 `memory` 没接上；正确表现是回答里出现「海外订单」相关的具体条款。

### 3.4.2 记忆选型：Memory vs ChatMemoryBuffer

| 需求 | 0.11/0.12 可用写法 | 0.12+ 推荐 |
| --- | --- | --- |
| 简单滑动窗口 | `ChatMemoryBuffer.from_defaults(token_limit=3000)` | `Memory.from_defaults(token_limit=3000)` |
| 会话跨进程持久化 | 需自己序列化 | `Memory.from_defaults(..., async_database_uri="sqlite+aiosqlite:///./chat.db")` |
| 长期事实抽取 | 无 | `Memory.from_defaults(memory_blocks=[FactExtractionMemoryBlock(...)])` |

```python
from llama_index.core.memory import Memory

memory = Memory.from_defaults(
    session_id="user-42",                                  # 同一用户跨请求复用
    token_limit=4000,
    async_database_uri="sqlite+aiosqlite:///./storage/chat.db",
)
```

> 走 `async_database_uri` 需额外装 `aiosqlite`（`pip install aiosqlite`），且 `Memory` 的读写是 async 接口；同步 `chat()` 里由框架内部转接，你若直接调 `memory.aget(...)` 要写 `await`。**需对照官方文档核实**你所用小版本的持久化参数名。

### 3.4.4 一个真实坑：condense 环节丢了上下文

`condense_plus_context` 先用 LLM 把「那海外订单呢」改写成独立问题，再检索。默认提示词是英文的，中文短问句常被改写成别扭的英文，检索命中率随之下降。解决办法是替换改写提示词：

```python
from llama_index.core import PromptTemplate

CONDENSE_TMPL = (
    "给定下面的对话历史和后续问题，把后续问题改写成一个不依赖上下文、可独立检索的问题。"
    "只用中文，不要回答问题，不要解释。\n"
    "对话历史：\n{chat_history}\n"
    "后续问题：{question}\n"
    "独立问题："
)

chat_engine = index.as_chat_engine(
    chat_mode="condense_plus_context",
    condense_prompt=PromptTemplate(CONDENSE_TMPL),
    similarity_top_k=3,
)
```

## 3.5 Agent 最小可运行示例

### 3.5.1 单 agent：能自己决定调工具的助手

```python
# agent_min.py
import asyncio

from llama_index.core import Settings
from llama_index.core.agent.workflow import AgentStream, FunctionAgent
from llama_index.core.tools import FunctionTool
from llama_index.llms.openai import OpenAI

Settings.llm = OpenAI(model="gpt-4o-mini", temperature=0.1)


def search_docs(query: str) -> str:
    """在内部文档库中检索与 query 相关的片段，返回拼接后的原文。用户问业务规则、条款、政策时必须先调用它。"""
    return str(index.as_query_engine(similarity_top_k=3).query(query))


def get_order_status(order_id: str) -> str:
    """按订单号查询物流状态。order_id 必须形如 A123456 才能查到。"""
    return f"订单 {order_id} 当前状态：已发货，预计 2 天后送达"


agent = FunctionAgent(
    name="SupportAgent",
    description="处理电商客服问题：查政策、查物流",
    tools=[
        FunctionTool.from_defaults(fn=search_docs),
        FunctionTool.from_defaults(fn=get_order_status),
    ],
    llm=Settings.llm,
    system_prompt=(
        "你是电商客服助手。回答业务问题时必须先调用 search_docs 检索，"
        "并在结论后给出来源文件的 file_name。不要编造条款。"
    ),
)


async def main():
    handler = agent.run(user_msg="A123456 什么时候到？顺便说下退款政策")
    async for ev in handler.stream_events():
        if isinstance(ev, AgentStream):
            print(ev.delta, end="", flush=True)
    final = await handler
    print("\nFINAL:", final)


if __name__ == "__main__":
    asyncio.run(main())
```

**三条必须遵守的约束**，违反任一条都会出现「agent 不调工具、直接编答案」：

1. 工具函数的 **docstring 就是工具的 description**，要写清「什么时候该用它」，而不是写实现说明。
2. 参数必须有类型注解，LLM 靠它生成调用参数；不要用 `*args` / `**kwargs`。
3. 返回值必须是字符串或可序列化结构，返回自定义对象前先转字符串。

### 3.5.2 模型必须支持 function calling

`FunctionAgent` 走 `chat_with_tools` 路径。若模型未宣告 `is_function_calling_model`，工具调用会走不通或退化成把工具描述塞进提示词。用 OpenAI 兼容接口时这是最容易踩的坑：

```python
import os
from llama_index.llms.openai_like import OpenAILike

# DeepSeek / Qwen 等兼容接口
Settings.llm = OpenAILike(
    model="deepseek-chat",
    api_base="https://api.deepseek.com/v1",
    api_key=os.environ["DEEPSEEK_API_KEY"],
    is_chat_model=True,
    is_function_calling_model=True,   # 关键：不显式置 True，FunctionAgent 可能不调工具
    context_window=65536,
)
```

> `api_base` 与 `base_url` 在不同小版本间存在差异，一个报参数错误就换另一个；`llama-index-llms-openai-like` 的 `OpenAILike` 默认 `is_function_calling_model=False`，这是设计行为不是 bug。

### 3.5.3 多 agent：AgentWorkflow + handoff

```python
from llama_index.core.agent.workflow import AgentWorkflow, FunctionAgent

research_agent = FunctionAgent(
    name="ResearchAgent",
    description="负责检索与整理事实依据",
    tools=[FunctionTool.from_defaults(fn=search_docs)],
    llm=Settings.llm,
    system_prompt="你只负责查资料。查完把要点交给 WriteAgent。",
    can_handoff_to=["WriteAgent"],
)

write_agent = FunctionAgent(
    name="WriteAgent",
    description="负责把事实要点写成给用户看的最终答复",
    tools=[],
    llm=Settings.llm,
    system_prompt="你只负责组织语言。缺少事实时把任务交回 ResearchAgent。",
    can_handoff_to=["ResearchAgent"],
)

workflow = AgentWorkflow(
    agents=[research_agent, write_agent],
    root_agent="ResearchAgent",   # 入口 agent 名（不同小版本参数名可能不同，需对照官方文档核实）
)

handler = workflow.run(user_msg="对比两版退款政策的差异，并写成一段给客户看的说明")
result = await handler
```

多 agent 的收益是「职责隔离 + 提示词互不污染」，代价是 token 与延迟成倍上升。**只有单 agent 的提示词已经长到互相干扰时再拆**，不要一上来就上多 agent。

### 3.5.4 0.10 旧写法对照（0.13 起已删除）

```python
# --- 0.10 及以前（现在会 ImportError）---
from llama_index.agent.openai import OpenAIAgent
agent = OpenAIAgent.from_tools(tools, verbose=True)

from llama_index.core.agent import AgentRunner, ReActAgent
agent = AgentRunner.from_llm(agent_cls=ReActAgent, tools=tools, llm=llm)

# --- 0.11+ 等价写法 ---
from llama_index.core.agent.workflow import FunctionAgent
agent = FunctionAgent(tools=tools, llm=llm)
handler = agent.run(user_msg="...")   # agent.run 返回 workflow 句柄，必须 await
result = await handler
```

**同步代码里怎么用？** `FunctionAgent.run` 返回的是 workflow 句柄，必须 `await`。在 FastAPI / Flask 里不要嵌套 `asyncio.run`（会报 `RuntimeError: asyncio.run() cannot be called from a running event loop`），应把接口写成 async，或把 agent 放到独立 worker 进程。
