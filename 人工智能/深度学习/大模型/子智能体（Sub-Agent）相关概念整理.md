# 子智能体（Sub-Agent）相关概念整理

---

## 1. 基础概念

### 主智能体（Master Agent / Orchestrator）

- **定义**：多智能体系统中负责全局推理、任务拆解与分发的核心智能体。它不直接执行具体领域任务，而是根据用户输入动态决策调用哪些子智能体，并汇总其返回结果形成最终输出。

### 子智能体（Sub-Agent / Domain Agent）

- **定义**：在多智能体架构中，接受主智能体委派、完成特定领域子任务的智能体单元。每个子智能体通常绑定特定的大语言模型、角色设定、工具集以及独立的上下文窗口，具备自主推理与多步执行能力。

---

## 2. 子智能体与工具调用的区别

### 工具调用（Tool Calling / Function Calling）

- **定义**：智能体在推理过程中，将某个无状态的函数或 API 作为外部工具进行单次调用，传入参数并获取返回结果，工具本身不具备自主推理或上下文维护能力。

### 子智能体调度（Sub-Agent Delegation）

- **定义**：主智能体将某个完整子任务连同上下文委派给另一个独立的智能体单元，该子智能体可进行多步推理、调用自身工具并维护内部状态，最终返回结构化结论或摘要。

### 核心区别

| 维度        | 子智能体调度                    | 工具调用              |
|-----------|---------------------------|-------------------|
| 推理能力      | 子智能体拥有独立 LLM，可自主推理        | 工具为无状态函数，无推理能力    |
| 上下文管理     | 维护独立上下文与执行历史              | 不维护上下文            |
| 任务粒度      | 适用于需要多步分析的复杂子任务           | 适用于单步查询或计算        |
| 返回信息      | 通常返回摘要或最终交付物              | 返回原始数据或简单结果       |
| Token 可见性 | 子智能体内部 Token 消耗不进入主智能体上下文 | 工具返回内容直接进入主智能体上下文 |

---

## 3. 路由与调度策略

### 硬编码路由（Hard-coded Routing）

- **定义**：在代码中通过关键字匹配或规则表达式判断用户意图，将请求固定转发至特定子智能体。实现简单但扩展性差，随子智能体数量增加维护成本线性上升。

### 基于大语言模型的路由（LLM-based Routing）

- **定义**：利用大语言模型的意图理解能力，通过分析用户输入动态决定应调用的子智能体及其参数。通常借助 Function Calling
  机制或文本解析（如 JSON 输出）实现，扩展性强，新增子智能体无需修改调度逻辑。

### 条件边（Conditional Edge）

- **定义**：在 LangGraph 等图编排框架中，根据当前状态中的特定字段动态决定下一执行节点的机制，用于实现主智能体到不同子智能体的路由分支。

---

## 4. Token 消耗与管理

### 上下文窗口（Context Window）

- **定义**：大语言模型单次推理所能处理的最大 Token 数量上限。在多智能体系统中，如果所有工具定义、子智能体完整输出和全量对话历史均加载至同一上下文，将迅速超出窗口限制。

### 摘要化返回（Summarized Response）

- **定义**：子智能体完成内部推理后，仅将最终结论或摘要返回主智能体，而非返回完整执行过程与中间输出，以减少主智能体上下文的
  Token 占用。

### 分层记忆（Hierarchical Memory）

- **定义**：将对话历史与知识划分为不同层级进行管理，例如工作记忆（当前上下文窗口）、短期记忆（向量数据库存储的近期摘要）和长期记忆（持久化的用户偏好与事实），按需检索而非全量加载。

### 上下文预算控制（Context Budget Control）

- **定义**：通过设置最大上下文长度、滑动窗口截断、消息压缩等手段，将主智能体的输入 Token 数量控制在预设范围内，防止多轮交互或大量子智能体结果导致
  Token 溢出。

---

## 5. 按需加载与动态工具注册

### 静态工具注册（Static Tool Registration）

- **定义**：在系统初始化时将全部工具或子智能体的定义一次性注入 Prompt 或上下文。当工具数量庞大时，会占用大量上下文窗口且增加决策困难。

### 动态工具检索（Dynamic Tool Retrieval）

- **定义**：根据用户输入实时从工具库中检索最相关的一小部分工具定义，仅将这部分候选工具注入主智能体的 Prompt。通常基于向量相似度检索实现。

### 工具嵌入索引（Tool Embedding Index）

- **定义**：将每个工具或子智能体的描述文本通过嵌入模型转换为向量，并存入向量数据库。用户查询时通过语义相似度检索获得最匹配的候选工具列表。

### 检索增强路由（Retrieval-Augmented Routing）

- **定义**：结合向量检索与大语言模型推理的两阶段路由策略。第一阶段通过嵌入检索筛选出 K 个候选工具，第二阶段由 LLM
  在候选工具中做出最终选择，兼顾效率与精度。

---

## 6. 用户问题的嵌入与拆解

### 意图拆解（Intent Decomposition）

- **定义**：对于包含多个独立需求的复合用户查询，先由大语言模型将其拆分为多个单一意图的子问题，再分别进行后续处理（如检索、路由），避免复合语义影响检索准确性。

### 查询向量化（Query Embedding）

- **定义**：使用嵌入模型将用户问题或子问题映射为固定长度的实数向量，作为在向量数据库中进行相似度检索的依据。

### 相似度阈值过滤（Similarity Thresholding）

- **定义**：在向量检索中设置最低相似度得分，仅保留相似度高于该阈值的工具或文档，防止低相关度结果进入上下文，减少无用 Token
  消耗。

### 多意图并行检索（Multi-Intent Parallel Retrieval）

- **定义**：对拆分后的多个子问题分别进行向量检索，合并去重后形成最终的候选工具集，确保每个子意图都有对应的工具被召回。

---

## 7. 常见架构模式

### 主-从式架构（Master-Worker Architecture）

- **定义**：由一个主智能体作为调度中心，多个子智能体作为执行单元，主智能体负责任务分配与结果汇总，子智能体负责领域内具体任务的完成。

### 图编排架构（Graph Orchestration）

- **定义**：使用有向有环图（如 LangGraph 的 StateGraph）定义智能体之间的执行流程，节点代表智能体或处理步骤，边代表控制流与数据流，支持循环、条件分支与人工介入。

### 子图嵌套（Subgraph Nesting）

- **定义**：在父图中将某个节点定义为另一个完整的子图（子智能体），父图只关注该子节点的输入输出，而子图内部的复杂流程对外部透明，实现模块化与
  Token 隔离。

---

## 8. 关键权衡与设计选择

| 设计维度     | 选项              | 说明                            |
|----------|-----------------|-------------------------------|
| 路由方式     | 硬编码 vs LLM 动态路由 | 简单场景可用硬编码；大规模、多领域场景需 LLM 动态路由 |
| 工具注册时机   | 静态全量 vs 动态按需    | 工具少时可全量加载；工具多时必须按需检索，控制 Token |
| 子智能体返回粒度 | 完整输出 vs 摘要      | 为减少主智能体 Token，一般要求子智能体返回摘要    |
| 多意图处理    | 单向量检索 vs 先拆解再检索 | 复合查询需先拆解，否则检索精度下降             |
| 记忆管理     | 全量历史 vs 分层记忆    | 长对话、多轮协作必须使用分层记忆与上下文裁剪        |
